# 事前問答腳本

用 AskUserQuestion 一次問 1–4 題，選項附說明；使用者已回答過的不再問。問答結果直接對應到 `cfg` 欄位（見 `config-reference.md`）。

## 0. 分流（一定先問）

> 「這份資料可以上傳讓我直接分析，還是屬於企業／非公開資料？」

- 可上傳 → 分支 1（公開資料）
- 企業／非公開 → 分支 2（只問結構、產出本機執行的 qmd 範本）
- 使用者已附檔但說是機密 → 立即停止讀取，不開啟、不摘要該檔，改走分支 2，並說明 Claude 沒有讀取內容。

## 1. 資料型態（兩條分支都要問；分支 1 可由資料自動判斷後再確認）

| 問題 | 選項 → cfg |
|---|---|
| 量測的是什麼？ | 連續量測值（尺寸、重量、溫度）→ `data_type = "variable"`；每件只分合格／不合格 → `"nonconforming"`；數缺點（一件可有多個）→ `"defects"` |
| 計量值：每次抽幾件？ | 每次 1 筆 → 個別值（不設 `col_subgroup`）；每次固定 n 件 → 子群，`declared$n = n, n_fixed = TRUE`；每次件數不固定 → `n_fixed = FALSE` |
| 計數值：每期檢查數量／暴露量固定嗎？ | 固定 → np／c；不固定 → p／u（`declared$size_fixed`） |
| 大約有幾組基準資料？ | 填 `declared$m1`（只要大約數量，不是數值內容） |
| 監測資料怎麼提供？ | 同一檔案以欄位標記 → `col_phase`；同一檔案以某編號切分 → `phase1_end`；兩個檔案 → `data_file_phase2`；沒有 → 全部當 Phase I |
| 有時間欄位嗎？ | 有 → `col_time`（程式依時間排序） |

不良品與缺點不能混用：「同一件有三個缺點」在不良品資料中仍只計 1 件。

## 2. 偵測目標

| 問題 | 選項 → cfg |
|---|---|
| 想偵測多大的均值偏移？（以製程標準差 σ 為單位） | 約 0.5σ／1σ／1.5σ 以上／不確定 → `delta = 0.5／1／2／NULL`。程式換算為輸入統計量的 $\delta_Y=\delta\sqrt n$，$\delta_Y<1.5$ 時加畫 EWMA／CUSUM（預設 $\lambda=0.2, L=3, k=0.5, h=5$）。 |

## 3. 製程背景（合理分組與 OCAP；只問類型與職稱）

| 問題 | 選項 → `cfg$process` / `cfg$ocap` |
|---|---|
| 子群怎麼抽？ | 同一時間點連續抽 n 件 → `sampling = "consecutive"`；分散在一段時間內抽 → `"spread"`；不確定 → `"unknown"` |
| 有哪些變異來源？（可複選） | 機台、模穴、班別、批次、換線 → `sources = c(...)`；同一子群是否混合不同來源 → `sources_mixed = TRUE/FALSE` |
| 量測系統 | 做過 MSA → `msa = "done"`；沒做過 → `"not_done"`；量具解析度可能不足 → `resolution = "poor"` |
| 抽樣間隔 | 文字，例如「每小時」→ `interval` |
| 失控時誰處理？（只問職稱） | 第一線、調查、決策角色 → `ocap$roles = list(first=, investigate=, decide=)` |
| 常見的可歸屬原因類型 | 例如原料批次、刀具磨耗、量具校正 → `ocap$causes` |

## 4. 分支 2 的隱私原則

**可以問：** 資料型態、子群大小、大約組數、欄位「種類」（有沒有時間欄、子群欄）、檔案格式、Phase 切分方式、抽樣方式、變異來源類型、是否做過 MSA、OCAP 角色職稱、常見原因類型。

**不問、也不接受：** 任何量測值、平均值、標準差、規格上下限、既有管制界限、產品名稱或料號、客戶名稱、人名、實際欄位名稱、資料樣本列、執行後的結果或截圖。

- 欄位名稱由使用者在 qmd 設定區自行填寫；Claude 只在設定區留下 `★ 請填寫` 與說明。
- 若使用者主動貼出數值或結果，不分析、不複述，提醒這些內容不需要提供，並繼續以結構資訊完成範本。
- 品質特性名稱可用代稱（例如「尺寸 A」）；`characteristic` 預設用使用者提供的代稱。
- 範本完成後不要求使用者回傳任何結果；所有判讀由範本內建的規則文字完成。

## 5. 分支 1 的失控點詢問

render（或直接執行 `spc_run`）後讀 `exclusions.csv` 中 `decision` 空白且目前仍有警報的點，用 AskUserQuestion 逐點（或每次最多 4 點）詢問：

> 「Phase I 第 15 組（np 圖，規則 1，偏高）：有沒有找到可歸屬原因？」
> 選項：找到原因且不屬於未來正常狀態 → 剔除（請在備註寫原因）／查無原因或屬正常狀態 → 保留／還不確定，先標為待查

依回答寫回 `decision`（`exclude`／`keep`）與 `reason`，再執行一次；剔除後出現的新警報會以下一輪附加，重複到沒有待查點。公開資料集若有文獻記載的原因（例如教科書範例），可提供給使用者確認，但決定仍由使用者做。
