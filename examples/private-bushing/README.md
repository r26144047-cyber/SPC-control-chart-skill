## 軸套外徑模擬資料：生成模型說明
### 1. 模型
 
這份資料由**常態獨立誤差**加上**人為埋入的偏移**組成。
 
第 $g$ 組第 $k$ 件（$g = 1, \dots, 45$ 、 $k = 1, \dots, 5$ ）的外徑為
 
$$
X_{gk} = \mu + \Delta_g + \varepsilon_{gk} + \eta_{gk},\qquad
\varepsilon_{gk} \overset{iid}{\sim} N(0,\ \sigma^2)
$$
 
### 2. 參數
 
| 符號 | 意義 | 設定值 |
|---|---|---|
| $\mu$ | 製程中心 | 25.000 mm |
| $\sigma$ | 組內（短期）標準差 | 0.010 mm |
| $\Delta_g$ | 第 $g$ 組整組的平均偏移 | 見第 3 節 |
| $\eta_{gk}$ | 單件的額外誤差 | 見第 3 節 |
| $n$ | 子群大小 | 5 |
| $m_1$ | Phase I 組數 | 25（第 1–25 組） |
| $m_2$ | Phase II 組數 | 20（第 26–45 組） |
 
**其他設定**
- **量測解析度：** 最後把數值四捨五入到 0.001 mm，模擬量具的解析度。
- **抽樣時間：** 從 2026-10-05 08:00 起，每 2 小時一組。08:00–20:00 標為早班，其餘標為晚班。
- **亂數：** 用 numpy 的 `default_rng`，種子 20261124，可完全重現。

### 3. 埋入的事件
<details>
<summary>點開查看</summary>
 
| 組別 | 現場事件 | 模型中的設定 | 偏移大小 |
|---|---|---|---|
| 第 7 組 | 分厘卡未歸零 | 只有第 3 件 $\eta_{7,3} = +0.045$ | 4.5σ，只影響單件 |
| 第 12 組 | 原料換批 | $\Delta_{12} = +0.020$ | 2σ，整組上移 |
| 第 31–45 組 | 更換刀具 | $\Delta_g = +0.006$ | 0.6σ，之後持續上移 |
| 其他組 | 無 | $\Delta_g =\eta_{gk} = 0$ | — |
 
**預期在管制圖上的表現**
- **第 7 組：** 只有一件偏大，組內全距會變大，所以預期 R 圖報警，X̄ 圖不會超界。
- **第 12 組：** 整組上移，全距不變，所以預期 X̄ 圖報警。
- **第 31 組起：** 換算到子群平均的尺度，偏移是 $0.6\sqrt{5} \approx 1.34$ 個 $\sigma_{\bar X}$。3σ 界限不容易抓到，要靠 WECO 規則、EWMA 或 CUSUM。
</details>

### 4. 模型隱含的假設
 
這些都是理想化的設定，真實資料通常不會這麼乾淨：
 
1. **組間沒有額外變異。** 正常狀態下，每組平均只受組內誤差影響，所以 $\bar R / d_2$ 估出的 σ 剛好等於總變異。真實製程常有班別或時間造成的組間變異，會讓 X̄ 圖出現很多假警報。
2. **時間上互相獨立。** 沒有自相關，不會觸發 AR(1) 殘差圖的路徑。
3. **分布是常態的。** 沒有偏態，假設檢查應該全部通過。
4. **偏移是瞬間階梯式的。** 換刀具後立刻上移、維持不變。真實的刀具磨耗比較像緩慢的線性漂移。
5. **班別欄只是標籤。** 模型裡沒有班別效果，拿它做分層比較應該看不出差異。
**這些假設讓 X̄–R 圖的前提全部成立，適合先確認分支 2 的流程能完整跑通。**
 
### 5. 生成程式（Python）
 
```python
import numpy as np, pandas as pd
 
rng = np.random.default_rng(20261124)
mu, sig, n = 25.000, 0.010, 5
m1, m2 = 25, 20
rows = []
t0 = pd.Timestamp("2026-10-05 08:00")
 
for g in range(1, m1 + m2 + 1):
    t = t0 + pd.Timedelta(hours=2 * (g - 1))
    shift = "早班" if 8 <= t.hour < 20 else "晚班"
    x = rng.normal(mu, sig, n)        # mu + epsilon
    note = ""
    if g == 12:                         # Delta_12 = +0.020
        x = x + 0.020
        note = "原料換批（新批號硬度偏高），第13組起恢復原批"
    if g == 7:                          # eta_{7,3} = +0.045
        x[2] += 0.045
        note = "量測員反映第3件讀值異常，事後發現分厘卡未歸零"
    if g >= 31:                         # Delta_g = +0.006
        x = x + 0.006
    if g == 31:
        note = "更換刀具（新供應商刀片）"
    for k in range(n):
        rows.append({
            "取樣時間": t.strftime("%Y-%m-%d %H:%M"),
            "子群編號": g,
            "樣本序": k + 1,
            "外徑_mm": round(x[k], 3),   # 解析度 0.001 mm
            "機台": "CNC-02",
            "班別": shift,
            "階段": "I" if g <= m1 else "II",
            "現場備註": note if k == 0 else "",
        })
 
df = pd.DataFrame(rows)
df.to_csv("軸套外徑_模擬資料.csv", index=False, encoding="utf-8-sig")
df.to_csv("軸套外徑_模擬資料_big5.csv", index=False, encoding="cp950")
```

### 為什麼用模擬資料集測試

這個範例要驗證的是分支 2 的承諾：**AI 沒看過資料，也能做出一份可在本機正確執行的範本**。

如果拿公開資料集來測（例如教科書或 R 套件內建的資料），AI 可能在訓練時就看過，甚至能從資料結構認出是哪一份，進而「知道」裡面的數值、失控點和結論。公開資料範例就是這種情況：Claude 從欄位和筆數就認出那是 qcc 套件的 `viscosity`。這樣就算範本跑出正確結果，也無法分辨是範本本身沒問題，還是 AI 早就知道答案、不知不覺照著答案設定。測試就沒有意義了。

所以這裡改用使用者**自己產生、從未公開過的模擬資料集**。AI 不可能事先看過它，對話中也只拿到結構和製程背景，從頭到尾不知道任何數值。範本在使用者本機跑出的結果，才能真正證明分支 2 的流程不靠 AI 看資料也能運作。
