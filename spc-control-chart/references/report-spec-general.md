# 一般讀者版 SPC 報告規格

改寫自使用者提供的「一般讀者版成果報告規格」，改為 SPC 管制圖情境。範本 `assets/template_general.qmd` 依此規格產生白話文字（`spc_plain_*()` 函式）；分析者可在 `<!-- 分析者補充 -->` 處補寫。只用於分支 1（分支 2 只交付統計版）。

## 讀者與定位

讀者沒有統計背景，想知道：製程穩不穩、哪裡出了問題、差多少、接下來怎麼做。與統計版共用同一份計算結果；可以省略方法細節，不可改變數字、範圍或結論，不可省略會改變判斷的限制。

## 格式

- 交付 qmd + HTML（不產 PDF）。大標題、大圖、短段落；第一屏就能看到答案。
- 程式碼放在對應段落之後，以 `code-fold` 預設收合（「顯示程式碼」）；共用函式放在最後「附：分析使用的程式工具」，同樣收合。
- 正文不放公式、診斷圖大全或模型輸出。

## 必要順序

1. **這份分析想回答什麼**：1–2 句重述問題（`purpose_plain`），交代基準期與監測期筆數、每筆代表什麼；有排除資料時一句話說明。
2. **最重要的發現**：先一句話回答（醒目框），再列 2–3 個結果：正常範圍（中心與上下界、單位）、監測期何時開始出現訊號與差多少、批內波動、基準期排除了哪些點與原因。仍有待查點時標示「暫定」。
3. **用圖表看結果**：2–4 張圖，圖說以發現為標題；主管制圖、批內波動圖（有時）、EWMA（有時）。每張圖下 1–2 句白話解讀。
4. **這些結果代表什麼**：基準是否可用；異常訊號＝值得調查、不等於知道原因；超出正常範圍≠產品不合格。
5. **可以如何參考**：OCAP 步驟表與負責角色；說明不能取代現場專業判斷。
6. **使用前要注意**：只列 2–4 項實際遇到的限制（待查點、自相關、分布不對稱、基準太少、過度離散、量測解析度），加上「訊號不代表原因、沒訊號不代表沒變化」。
7. **名詞小解釋**：只列正文實際用到的詞（正常波動範圍、中心線、異常訊號、基準期／監測期；有時加批內波動、EWMA）。

## 白話轉寫

| 避免 | 改寫 |
|---|---|
| UCL／LCL | 正常波動範圍的上界／下界（第一次出現時括號註明「管制界限」） |
| CL | 基準期的中心（平均水準） |
| 失控、OOC | 出現異常訊號，值得調查 |
| Phase I／II | 基準期／監測期 |
| WECO 規則 2–4 | 連續多點偏向同一側 |
| 製程穩定 | 在這段期間沒有出現需要調查的異常訊號 |
| 偏低（計數圖） | 不良變少，可能是改善，也可能是判定標準或檢驗方式改變 |

## 禁止事項

- 不寫成因果（「造成」「導致」），不把訊號寫成已確認的原因。
- 不把「沒有訊號」寫成「製程沒有問題」。
- 不捏造原因、案例或單位；所有數字來自實際計算，並附單位與比較基準。
- 不放規格、能力指標，不宣稱可直接自動決策。

## 交付前檢查

- 只看第一屏，是否知道答案與最重要的限制？
- 每個數字是否有單位與比較基準？
- 是否與統計版的數字、圖與結論一致？
